# 共通行動規範

全作業に例外なく効く規範のみを置く。特定の作業だけに効くものは T1（`paths:` 付き）へ。

- **完了の定義**: メインエージェントは、commit 前に build・test・lint を通す ／ 例: `npm run build && npm test && npm run lint` ／ 失効: CI が必ず同等の検査で落ちる構成になったら
- **commit 粒度**: メインエージェントは、1 commit = 1 機能または 1 修正で切り、各 commit を単体でテストが通る状態に保つ ／ 例: 実装と無関係な整形は別 commit にする ／ 失効: なし
- **承認が要る操作**: メインエージェントは、main への push / PR merge / 本番 deploy / DB migration / secrets 操作の前にユーザー承認を取る（頼み方は「承認はカードで求める」参照） ／ 例: `git push origin main` は提案して止まる（`settings.json` の `ask` でも止まる） ／ 失効: なし
- **`loop`（自動で進む）のとき**: メインエージェントは、`mode.yml` が `loop` のとき確認を求めず作業を続ける。
  止まるのは 3 つ — ユーザーの停止指示 / タスク完了 / 続けられないエラー。
  新しい設計の追加・決めた内容の変更・元に戻せない操作は、`loop` でも承認を取る ／ 例: 実装中の方式選択は自律、新しい設計メモの起案は承認 ／ 失効: なし
- **設計の起点**: メインエージェントは、現在形の文書（仕様・設計・規範）を変える依頼を、会話・会議・Slack・issue で決まったことも含めて、分かれ道（A 提案なし／B 決定だけ ADR／C 提案が要る。判定の表は `/hirai-lite:new-draft`）にかけ、C は `docs/draft/` に起こして承認後に task にする（PR で承認する運用では、提案の決定〔ADR〕が承認済みで未裁定の論点が 0 件になったら、設計 PR の merge を待たずに task にし、依存の無い task から着手する。台帳の形は `/hirai-lite:new-task`、GitHub Project の形は `hirai-task new`）
  ／ 例: 「ログイン失敗の上限を 5 回にする」は受入が変わるので `docs/draft/login-limit.md` → 承認 → task ／ 失効: なし
- **事実で答える**: メインエージェントとサブエージェントは、ファイル・コマンド結果・外部仕様を述べるとき根拠を併記する。
  ファイルは `path:line`、コマンドは実行したコマンドと exit code、外部仕様は URL。
  根拠を示せないときは「未検証」と明記する。ユーザーへの報告は結論と意味を先に書き、詳細をあとに置く ／ 例: 「9 case PASS（`bash tests/smoke.sh`、exit 0）」 ／ 失効: なし
- **宣言と実体を突き合わせる**: メインエージェントは、設定やマニフェストを変えたら、反映された件数・値を実測して期待値と比べる ／ 例: `claude plugin details <name>` の登録件数をリポジトリ内の実ファイル数と突き合わせる ／ 失効: なし
- **否定は肯定を出せると確かめてから報告する**: メインエージェントは、「0 件」「無い」「衝突しない」と報告する前に、そのコマンドが該当ありのとき何を出すかを 1 度確かめる ／ 例: `git merge-tree` が衝突 0 と出たら、衝突する既知の 2 ブランチで同じ形式を叩いて表示を見る ／ 失効: なし
- **テストは壊して確かめる**: メインエージェントとサブエージェントは、新しい検査かテストを足したら、対象（検査の入力・本番コードの 1 行）を故意に壊して FAIL することを確認してから採用する ／ 例: `paths:` を 1 行消したコピーで層違反検出が FAIL するか、本番の条件式を反転してテストが赤になるか見る ／ 失効: なし
- **同種の欠陥を横に探す**: メインエージェントとサブエージェントは、1 箇所直したら同じ原因の箇所を grep で全部洗い、同じ commit で直す ／ 例: 場所の決め打ちを 1 コマンドで直したら、残る解決経路とコマンドも同時に直す ／ 失効: なし
- **ルール追加の窓口**: メインエージェントは、新しい規範を思いついたら `_meta.md` のパイプラインを通す ／ 例: `/hirai-lite:add-rule "完了は PR で閉じる"` ／ 失効: なし
- **承認はカードで求める**: メインエージェントは、承認・判断・人の作業を頼むとき、1 行目に結論（「決めること」と「推奨」。人の作業は「やること」）を置き、目的 / 位置 / 承認すると（戻せるか）/ しないと / 注意 を 400 字以内で書く。**番号は最後の行、元に戻せない操作とルールの追加は全文をカードの下に** ／ 例: 「決めること: ログインの試行に上限を設けるか。推奨: 承認する」 ／ 失効: なし
- **作業の起点は task**: メインエージェントは、着手前に task の本文と依存を読み（GitHub の形は `gh issue view <n>`、台帳の形は `docs/tasks/list.md` と task ファイル）、`/hirai-lite:start-task` で 進行中 にする ／ 例: `/hirai-lite:start-task 12` ／ 失効: task の正本を持たない運用にしたとき
- **重い作業は委譲する**: メインエージェントは、複数ファイルにまたがる調査・実装・検証を subagent へ `run_in_background: true` で委譲し、待機中も別の作業を進める ／ 例: 実装を 4 分割して subagent に配る ／ 失効: なし
- **委譲のモデル**: メインエージェントは、手順と合否が決まっている作業（実装・スクリプトを回す検証・調査・結果の分類）の委譲に `model: sonnet` を、何を問題とみなすかの判断が成果物になる作業（観点別レビュー・反証・案の比較・指摘の統合）の委譲に `model: opus` を渡す。Workflow ツールの `agent()` にも同じ基準で渡す ／ 例: 指摘がコード上で成り立つかの反証は opus、`npm test` を回す検証は sonnet ／ 失効: 引数で渡さなくても agent 定義と親の既定だけで同じ割り当てになったとき
- **GitHub のデータはメインが 1 回取って渡す**: メインエージェントは、subagent に GitHub を叩かせず、要るデータを先に 1 回取ってファイルで渡す。subagent は `gh` を実行しない ／ 例: `gh issue list --json number,title > .tmp/issues.json` を渡し、subagent は python3 で読む ／ 失効: GraphQL 枠が枯れなくなったとき
- **同時起動は 2 件まで**: メインエージェントは、Agent tool で直接起動する subagent と Workflow ツールの実行をそれぞれ同時 2 件までにし、完了通知を受けてから次を起動する。Workflow ツール内部の同時数はランタイムに、総数は `workflowSizeGuideline` の目安に任せ、内部のエージェントにも subagent 向けの規範を当てる ／ 例: 実装 4 分割なら 2 件ずつ 2 回、Workflow ツールなら 1 本にまとめる ／ 失効: メインが直接起動する subagent を同時 4 件以上走らせても安定して完走するようになったとき
- **レビューは並列で立てる**: メインエージェントは、成果物ができた時点で、実装の担当の報告に名の無い異なる観点の reviewer を 2〜3 本並列起動し（報告の「要判断」は reviewer に渡さずユーザーへ回す）、同じ指摘を 1 行にまとめて最も重い重さを付け、HIGH 以上の行にだけ反証を 1 本ずつ立てる。ultracode でも同じ ／ 例: 観点 3 本（`/code-review` の正しさ・脆弱性・テスト）を Workflow 1 本で回し、まとめて HIGH 1 件なら反証 1 本の計 4 本 ／ 失効: なし
- **Workflow の args**: メインエージェントは、Workflow ツールの args を python でファイルに作って件数を assert し、そのファイルの中身を貼ってから呼び、script の 1 行目で args の形を検査する ／ 例: `python3 mk_args.py > args.json && cat args.json` の出力を args に貼る ／ 失効: Workflow ツールが args の形を宣言で検査するようになったとき
- **委譲中は branch を固定する**: メインエージェントは、subagent が走っている間は作業ツリーの branch を固定し、`git switch` / `git checkout <branch>` / `git stash` は `ListAgents` で running が 0 になってから実行する ／ 例: 別 branch へ移す記録は subagent の完了通知を待ってから commit する ／ 失効: 実装 subagent の既定が `isolation: 'worktree'` になったとき
- **判断を求められたら止まる**: サブエージェントが「要判断」を返したとき、メインエージェントは user に判断カードを出して指示を待つ ／ 例: 「選択肢: A … ／ B …」「推奨: A — 理由」と期限を示す ／ 失効: なし
