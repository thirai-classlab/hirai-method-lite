版の付け方は [semver](https://semver.org/lang/ja/)。`VERSION` と `.claude-plugin/plugin.json` の `version` は常に同じ値を持ち、`tests/smoke.sh` が一致を検証する。tag は `hirai-project-method--v<版>`。

## v1.2.0
全体の進みと、振っているタスクの順番・進捗率の表（GitHub Project と PR・CI の実物から）を、道具の側で出す形にした（heyapro-app の #1978）。土台の動きは変えていない（土台は 3.1.0 のまま。直したのはリポ直下の README とカタログの説明文だけ）。

- **`hirai-task load`**（新）: 4 部の表（1 行目の完了の率・セクションの表・進行中のタスクの表・実物と合っていない行）を出す。進捗は申告でなく実物で決める: 0 着手前／20 進行中・レビュー中（PR なし）／50 draft／60 ready で CI が走っているか赤・検査なし／70 CI 緑／90 merge 済みで issue が開いている（Status が 完了 の開いた issue も）／100 閉じた。**控えに無い（新しい）issue は 0% で、完了に数えない**。CI が赤・衝突した task は「止まっているもの」の行に出す。板は `board` の控え（10 分）を使い、PR・CI・進行中の task の Assignees は 1 回の GraphQL で引く（CI は `statusCheckRollup` の集約。Assignees は 50 件ごと・500 件まで）。`--json`・`--changed`（前回から段・担当・順番・止まりの印が動いたときだけ出し、動いていなければ 1 行も出さず exit 3）・`--cached`（gh を叩かず手元の控えだけ読む）・`--refresh`・`--if-coordinator`（コーディネーターの会話でなければ exit 3）
- **`hirai-task assign <n> <作業のセッションの名前> [順]`・`assign <n> --clear`**（新）: 手元の控え（git の管理ディレクトリの下の `hirai-task/load-assign.json`。同時に書いても失わない）に書く。Project に「担当」の項目は足さない・書かない
- **Assignees**: `start` と `assign` は、Assignees が空なら動かしている GitHub ユーザーを入れる。ほかの人（複数人を含む）が入っていたら警告を 1 行出す（その人の開いている PR も）。空でも、ほかの人の開いている PR がその task を閉じるなら、入れずに警告する。上書き・追加・停止はしない。確かめられないときは標準エラーに 1 行で、着手や割り振りの結果（exit code）は変えない
- **表が出るとき**: `start`・`done`・`after-merge`・`assign` の終わり（コーディネーターの会話だけ）。コーディネーターの会話 = `HC_NOTIFY=off`（土台の知らせと同じ印）・`notify: orca` と `tasks: github-project` のリポ・Orca の端末・linked worktree でない、の全部。`start`・`done` の変更は板の控えが追いつくまで表に重ね、10 分より古い控えで描くときは「（控え: N 分前）」を出す
- **`hooks/coordinator-load.sh`**（新・PostToolUse の Bash・42 行）: コーディネーターの会話が `orca orchestration check` で担当の知らせ（message）を受けたとき、「`hirai-task load --changed` を打つ」の 1 行を会話に足す。**止めない**（操作の可否を変えない・常に exit 0・失敗と対象外では何も出さない）・GitHub を叩かない・控えも読まない（古い控えの表を「動いた」と見せないため）
- **skill `github-project`** に「進みと割り振りの表」の節と、「進捗を見せて」などの呼び出し口を足した（`board` は「どこで何件止まっているか」、`load` は進捗と割り振り）
- **設定（任意・そのリポの `.claude/mode.yml` だけ）**: `load_deadline: YYYY-MM-DD`（本文に「期限: <日付>」の行がある open の issue を REST の検索で数える。日付に触れただけの issue は数えない）・`load_deadline_label`・`load_mainline`・`load_mainline_label`。無い設定の行・印は出さない
- **費用**（2026-11-25 に本物の Project〔1,804 行〕で読みだけ実測。書き込みなし）: 控えが無いとき 56 秒・GraphQL 約 23 点（`board` の取得と同じ）、10 分以内の控えがあるとき 3〜4 秒・1 点（PR と Assignees の 1 回）、`--cached` は 0 点・1 秒未満。期限の設定があると REST の検索が 1 回（100 件ごと）足される。`start`・`assign` は REST 2〜3 回（`user`・issue・Assignees）と、Assignees が空かほかの人のときだけ PR の GraphQL 1 回が増える（表が出る会話では、書いたあとの表でもう 1 回。待ちは最大 25 秒で打ち切る）
- **限界**: PR は開いているものが 50 本まで（超えたら表に 1 行）・merge 済みは更新の新しい 50 本だけを見る（外れた merge 済みの task は 20% になる）。hook は知らせを受けたときだけ出て、担当の知らせが無い変化（画面での merge など）は `hirai-task load --changed` を打つと出る。表の「止まっているもの」は CI の赤と衝突だけ
- **検査**: `hirai_task_selftest.py` の load・assign・Assignees・コーディネーターの判定・配線と、`tests/smoke.sh` case 7（hook）。`load` を 64 通り・hook を 8 通り壊して、どれも落ちることを確かめた
- **導入先で要る操作**: `/plugin marketplace update hirai-lite` → 端末で `claude plugin update hirai-project-method@hirai-lite --scope <入れた範囲>` → 会話の開き直し（足すプラグインは tag を待たずに `main` から届く。v1.1.0 の項と同じ）。コーディネーターの会話は `HC_NOTIFY=off claude` で開く（付けないと、表も hook の 1 行も出ない）

## v1.1.0
見回り（`hirai-task today`）の直し 3 つと、`bug` の定義 1 行（土台 3.1.0 の `/hirai-lite:new-task`）。**見回りが書くものが 1 種増える**（align・close-parents に、閉じたのに完了でない task への Status=完了 が加わる）。

- **閉じたのに完了でない → 完了を書く**: `today` は、閉じているのに Status が 完了 でない task のうち、**今の Status が 進行中・レビュー中・空 で、[操作]・[User] でない task（この repo の行だけ）** へ Status=完了 だけを書く（種別が feature・wave・設計メモ でない行）。閉じた理由が not planned でも同じ（`done --not-planned` が書く Status も 完了）。**[操作]・[User] と、承認待ち・判断待ち・依存待ち・着手可・保留 のまま閉じた行は書かず、1.0.0 と同じく stuck に番号と題を出すだけ**（誤って閉じた task・実行していない操作がありうる。完了になると wave の「子の条件」も満たしてしまう）。書く前に「閉じたのに完了でない task を完了にする（対象 N 件・1 回 5 件まで）」と出し、**1 件書くたびに `完了にした: #n（前の Status → 完了）題` を 1 行出す**（時間切れで止められても何を書いたかが残る）。item id と選択肢 id を先に引き、そのあとで state・種別・Status・題を読み直して（GraphQL 1 回）、書く相手でなければ飛ばし、読み直した直後に item_id を渡して書く。PATCH の応答に item の id が無ければ、書けたと数えず journal にも残さない。1 件書けなくても理由を 1 行出してほかを続け（想定外の形の応答も 1 件の失敗として「想定外の応答: <型>」と出し、today のほかの段まで進む）、rate limit・権限の 403 なら残りを打ち切る（判定は gh の失敗の文だけを見る。issue 番号の 403・429 を HTTP の番号と読まない。JSON でない `HTTP 429`・`HTTP 403` と abuse の文も読む。文も分ける。rate limit の回は align も一覧だけにして、書き込みを重ねない）。書けない行は stuck に残る（別の repo の行は repo 名を添える）。align・close-parents と同じ許可（切り替え・open の issue の「- today は書かない: はい」）に従い、journal に `close-sync` で 1 件ずつ残す。**1 回 5 件・45 秒まで**（失敗・飛ばしは書けた枠に数えない。書き込みの間は 8.5 秒、最後は待たない。検索に出ない行の引き直しは待たない）。**次の today は試した番号の続きから回す**（共有の控え `gh-closed-done-cursor.json`。1 件試すたびに書くので、途中で切られても続きから。書けない行が先頭に並んでも後ろに届く）。journal や控えが書けないときも警告 1 行で続け、`today | head` で出力先が閉じても stdout を捨てて続ける。today に `--json`・`--dry-run` などの引数は無く、付けると exit 2。書いた行は、取り直した板でも state が CLOSED の行だけ 完了 として以降の段が見る。GraphQL は、書く相手 1 件につき 1 回（読み直し）と、書いた回の owner の種類の問い合わせ 1 回・終了時の件数の控えの取り直し（最大 2 回）が増える。
- **「この repo の行だけ」は完了の書き込みだけの決まり**: align・close-parents・目印の照合は、複数のリポを載せた Project で別 repo の行を絞らない（1.0.0 と同じ）。別 repo の行の番号でこの repo の issue を閉じうる・別 repo の OPEN の行があると today が落ちうるのは、別の task で直す。
- **種別なしに直すコマンド**: orphans の「種別なし」の行の次に `直す（feature・wave・設計メモならその値）: hirai-task set <n> 種別 task` を出す（コロンの後ろはそのまま打てる。別 repo の行には出さない）。`set`・`start` は、相手の種別が空なら stderr に同じ直し方つきの警告 1 行（止めない・exit code は変えない。種別自身の `set` は警告しない）。種別の項目が無い Project では、どちらも出さない。
- **no-issue の merge**: 直近 7 日に `no-issue` ラベルで merge された PR を「no-issue の merge（7 日）N 件: #a・#b」の 1 行で出す（0 件なら出さない。ただし 100 件で見切れているときは 0 件でも「0 件」と出す）。既定の branch 向けの PR だけを数える（設計の PR も入る）。merged-designs が読む closed の PR 100 件を共有し、API は増えない。100 件で 7 日に届かないときは「（7 日・直近の closed PR 100 件まで）」と添える。ラベル名は `NO_ISSUE_LABEL` の 1 か所。
- **merged-designs**: 本文の印 `pr-template-design-v1` に加え、「種別: 設計・決定の文書」の行（土台 3.1.0 の PR の雛形）でも設計の PR を見分ける。
- **検査**: `hirai_task_selftest.py` に、書く相手（進行中・レビュー中・空 だけ。目印・ほかの Status・feature は書かない）・読み直しで動いた行（reopen・Status・種別・題・404・null・Project に居ない）・許可なし・書けない 1 件＋書ける 1 件・rate limit（403・429・HTTP の数字なし・GraphQL の errors）と権限の 403・番号 403／429 の issue・45 秒と 5 件の上限・続きから回ること（途中で切られた回・rate limit の回も）・控えの中身と置き場所と壊れた値・待ちの回数・rate limit の回の align・journal と控えの失敗・想定外の形の応答 7 通り・PATCH の応答に id が無い形 5 通り・出力先が閉じたとき・種別なしの直し（出た文の命令をそのまま打って通る）・set と start の警告・no-issue の 0 件／3 件／6 日前／8 日前／境目／100 件で切れる・closed の PR を 1 回だけ読む、などを足した。偽の板の行は url を持ち、別 repo の同じ番号・書く順・GraphQL の回数・today の引数も見る（実装を 1 か所ずつ壊した写し 53 本で落ちることを確かめた）。
- **注だけの直し**: `scripts/ghp-path.sh` の注 2 か所の「5 秒」を、土台の今の SessionStart の制限（3.0.1 から 30 秒）に直した（動きは変わらない）。
- **届く時点（tag を待たない）**: 足すプラグイン 1.1.0 は、`main` に入った時点で届く（`claude plugin update` か自動更新。tag は要らない。2026-11-24 に手元の git source で実測。自動更新の経路は未検証）。tag を待つのは、足すプラグインも入れたリポの**土台**だけ（`hirai-lite--v3.1.0` を打つまで 3.0.1 のまま）。だから tag の前は「土台 3.0.1 × 足すプラグイン 1.1.0」の組になり、`today` は 1.1.0 の決まりで 完了 を書く。止めたいときは merge の前に止める。tag `hirai-project-method--v1.1.0` は記録のため（打っても届き方は変わらない）。
- **導入先で要る操作**: `/plugin marketplace update hirai-lite` → 端末で `claude plugin update hirai-lite@hirai-lite --scope <入れた範囲>` と `claude plugin update hirai-project-method@hirai-lite --scope <入れた範囲>` → 会話の開き直し。届いたかは `claude plugin list` の `hirai-project-method` の版が `1.1.0`（または `1.1.0-<12 桁>`）かで見る。土台への依存は `hirai-lite >=3.0.0` のまま。
- **戻すとき**: `main` を revert すると足すプラグインは 1.0.0 に下がるが、足すプラグインを入れたリポの土台は tag `hirai-lite--v3.1.0` が残る間 3.1.0 のまま（土台の CHANGELOG の「戻し方」）。

## v1.0.0
hirai-lite 2.9.0 の GitHub Project の部品を、土台（hirai-lite 3.0.0）から分けて足すプラグインにした。設計: hirai-lite の設計「hirai-lite を土台にし、GitHub Project のタスク管理を hirai-project-method に分ける」（2026-11-23 承認）。

- **移したもの**（`git mv`。履歴は hirai-lite 2.9.0 から続く）: `bin/hirai-task`・`scripts/hirai_board.py`・`hirai_card.py`・`hirai_project_setup.py`・`hirai_task_selftest.py`・`commands/board.md`・`commands/project-setup.md`・`skills/github-project/`・`docs/rules-reference/project-setup.md`・`glossary.md`・土台の `scripts/tasks-path.sh` の GitHub Project の関数（`harness_ghp_*`）。
- **`scripts/ghp-path.sh`**: 上の関数の置き場。土台の関数には依存しない。控えの置き場の id は `hirai-project-method-hirai-lite`（`~/.claude/plugins/data/` の下）。2.x の控え（`hirai-lite-v2-hirai-lite`）は読まない。件数は初回の取り直しで作り直される。
- **`hirai-task line [--refresh]`**（新）: 会話の開始時と画面下に出す「やること」の 1 行（件数の控えを読むだけ）を出す。控えが無い・form が ghp でないときは何も出さず exit 0。`--refresh` を付けると出したあとに背景で取り直す（Project の見分けは 24 時間に 1 回・件数は 2 分に 1 回まで）。付けない呼び出しは gh を打たない。土台の `hooks/session-start.sh`（`--refresh` つき）と `scripts/statusline.sh`（なし）が、`.claude/mode.yml` の `tasks: github-project` のときだけ呼ぶ。
- **`hirai-task today` の前夜の CI の 1 行**（新）: `.claude/mode.yml` の `nightly_ci: <workflow のファイル名>` があるとき、`today` の先頭に直近の schedule の run の結果を 1 行出す（`前夜の CI（ci.yml・11-24 03:17）: 成功`。失敗は url つき・実行中・run が無い・取れない（理由）は別の文。時刻は JST。36 時間より古ければ注記）。値は足すプラグインの中の読み方（土台の `harness_yml_value` と同じ規則: プロジェクト → ホーム・引用符と行末の注を外す）で読み、空か無ければ何も出さず gh も呼ばない。
- **`hirai-task after-merge` の末尾の 1 行**（新）: 土台の `hirai-worktrees list` で消してよい worktree が 1 本以上あるとき「消してよい worktree: N 本（うち退避が要る M 本。`hirai-worktrees list` で見る）」を出す（0 本なら出さない）。
- **呼び名**: `/hirai-project-method:board`・`/hirai-project-method:project-setup`（2.x の `/hirai-lite:board`・`/hirai-lite:project-setup` から変わる）。
- **依存**: `plugin.json` の `dependencies` に `hirai-lite >=3.0.0`。土台が無いと読み込まれない。自己検査（`hirai-task --selftest`）は土台の `docs/rules-reference/approval-template.md` と `templates/draft.md` を読むので、土台の場所を `HIRAI_LITE_ROOT`・リポ内の配置・`installed_plugins.json` の `hirai-lite` の順に探す。
